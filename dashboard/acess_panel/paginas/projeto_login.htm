SISTEMA-LOGIN: BACKEND REFORÇADO

1. Visão Geral do Ecossistema

O Sistema-login opera sob o paradigma de Programação Orientada a Objetos (POO) e utiliza a camada de abstração PDO para garantir que as consultas SQL sejam imunes a SQL Injection.

Funcionalidades de Soberania:

  • Validação de Unicidade: Verificação em tempo real de e-mails já existentes no banco.
  • Área Restrita: Proteção de rota que exige token de sessão válido.
  • Evolução do Hashing: Migração de MD5 (limitado) para VARCHAR(255) visando suporte a algoritmos modernos como BCRYPT.

2. Configuração Crítica de Rede (XAMPP)

Configuração de portas para evitar conflitos no ambiente Brotherhood:

Apache HTTP: 8080
Apache HTTPS: 4433
MySQL: 3306
Nota de Conexão: O PHP deve apontar explicitamente para localhost:8080 no tráfego HTTP.

3. Estrutura de Iniciação SQL (Atualizada)

Abaixo, a estrutura de tabela corrigida para suportar hashes de segurança longos e codificação internacional:

CREATE DATABASE projeto_login;
USE projeto_login;

CREATE TABLE usuarios(
    id_usuario INT AUTO_INCREMENT PRIMARY KEY,
    nome VARCHAR(30),
    telefone VARCHAR(30),
    email VARCHAR(40),
    senha VARCHAR(255) NULL -- Expandido de 32 para 255 (UTF8MB4)
) CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
LOG DE MANUTENÇÃO: Devido à alteração do campo senha de VARCHAR(32) para VARCHAR(255) e ajuste de Collation, todas as contas de teste criadas anteriormente foram expurgadas do banco. Foi necessário recriar os logins para garantir a integridade dos novos valores de hash.

4. Didática: Implementação PDO

Exemplo de inserção segura utilizando o novo padrão de campo:

// O VARCHAR(255) permite o uso de password_hash()
$senha_segura = password_hash($senha_usuario, PASSWORD_DEFAULT);

$sql = $pdo->prepare("INSERT INTO usuarios (nome, email, senha) VALUES (:n, :e, :s)");
$sql->bindValue(":n", $nome);
$sql->bindValue(":e", $email);
$sql->bindValue(":s", $senha_segura);
$sql->execute();
