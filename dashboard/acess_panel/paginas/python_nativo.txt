O PIPENV

O Pipenv e o venv criam ambientes virtuais isolados para projetos Python, evitando conflitos de bibliotecas. Use pipenv (mais moderno) para gerenciamento automático de dependências (Pipfile) e venv (nativamente integrado) para projetos mais simples. 

Exemplo: python -m venv bla-bla-bla

1. Pipenv (Recomendado)
O Pipenv une pip e virtualenv em uma única ferramenta. 

Instalação: pip install pipenv
Criar e Ativar: pipenv shell (executar dentro da pasta do projeto)
Instalar pacotes: pipenv install <nome_do_pacote>
Instalar dependências do Pipfile: pipenv install
Sair: exit 

2. venv (Nativo do Python) 
O venv é incluído no Python e cria uma pasta local para o ambiente. 

Criar: python -m venv venv (ou python -m venv .venv)
Ativar (Windows): .\venv\Scripts\activate
Ativar (Linux/macOS): source venv/bin/activate
Instalar pacotes: pip install <nome_do_pacote>
Desativar: deactivate 

Resumo das Diferenças:

Característica 	Pipenv	venv
Gerenciamento	Automático (Pipfile)	Manual (requirements.txt)
Ativação	pipenv shell	source/activate
Uso principal	Projetos complexos	Projetos simples/scripts

INSTALANDO PACOTES  

Esta seção aborda os conceitos básicos de como instalar pacotes Python .

É importante notar que o termo "pacote" neste contexto está sendo usado para descrever um conjunto de softwares a serem instalados (ou seja, como sinônimo de distribuição ). Não se refere ao tipo de pacote que você importa no seu código-fonte Python (ou seja, um contêiner de módulos). É comum na comunidade Python se referir a uma distribuição usando o termo "pacote". O uso do termo "distribuição" geralmente não é o preferido, pois pode ser facilmente confundido com uma distribuição Linux ou outra distribuição de software maior, como o próprio Python.

Criação de Ambientes Virtuais 
Os "ambientes virtuais" do Python permitem que pacotes do Python sejam instalados em um local isolado para uma aplicação específica, em vez de serem instalados globalmente. Se você deseja instalar ferramentas de linha de comando globais com segurança, consulte Instalando ferramentas de linha de comando independentes .

Imagine que você tenha um aplicativo que precisa da versão 1 do LibFoo, mas outro aplicativo requer a versão 2. Como você pode usar ambos os aplicativos? Se você instalar tudo em /usr/lib/python3.6/site-packages (ou qualquer que seja o local padrão da sua plataforma), é fácil acabar em uma situação em que você atualiza inadvertidamente um aplicativo que não deveria ser atualizado.

Ou, de forma mais geral, o que acontece se você quiser instalar um aplicativo e deixá-lo funcionando normalmente? Se um aplicativo funciona, qualquer alteração em suas bibliotecas ou nas versões dessas bibliotecas pode quebrar o aplicativo.

Além disso, o que acontece se não for possível instalar pacotes no diretório global site-packages? Por exemplo, em uma hospedagem compartilhada.

Em todos esses casos, os ambientes virtuais podem ajudar. Eles possuem seus próprios diretórios de instalação e não compartilham bibliotecas com outros ambientes virtuais.

Atualmente, existem duas ferramentas comuns para criar ambientes virtuais em Python:

O venv está disponível por padrão no Python 3.3 e versões posteriores e instala o pip em ambientes virtuais criados no Python 3.4 e versões posteriores (versões do Python anteriores à 3.12 também instalavam o Setuptools ).

O virtualenv precisa ser instalado separadamente, mas é compatível com Python 2.7+ e Python 3.3+, e o pip , o Setuptools e o wheel são instalados por padrão nos ambientes virtuais criados. Observe que o pipsetuptoolsnão é mais incluído por padrão a partir do Python 3.12 (evirtualenvsegue esse comportamento).

O uso básico é o seguinte:

Usando venv :

Unix/macOS
python3 -m venv <DIR>
source <DIR>/bin/activate

Windows
Utilizando ambiente virtual :

Unix/macOS
python3 -m virtualenv <DIR>
source <DIR>/bin/activate

Windows
Para obter mais informações, consulte a documentação do venv ou a documentação do virtualenv .

O uso do comando `source` em shells Unix garante que as variáveis ​​do ambiente virtual sejam definidas dentro do shell atual, e não em um subprocesso (que então desaparece, não tendo nenhum efeito útil).

Em ambos os casos acima, os usuários do Windows não devem usar o comando `source` , mas sim executar o script de ativação diretamente do prompt de comando, da seguinte forma:

<DIR>\Scripts\activate
Gerenciar vários ambientes virtuais diretamente pode se tornar tedioso, então o tutorial de gerenciamento de dependências apresenta uma ferramenta de nível superior, o Pipenv , que gerencia automaticamente um ambiente virtual separado para cada projeto e aplicativo em que você trabalha.

Use o pip para instalar 
O pip é o instalador recomendado. Abaixo, abordaremos os cenários de uso mais comuns. Para obter mais detalhes, consulte a documentação do pip , que inclui um Guia de Referência completo .

Instalando a partir do PyPI 
O uso mais comum do pip é instalar pacotes a partir do Índice de Pacotes Python (PyPI) usando um especificador de requisitos . De modo geral, um especificador de requisitos é composto por um nome de projeto seguido por um especificador de versão opcional . Uma descrição completa dos especificadores suportados pode ser encontrada na especificação de especificadores de versão . Abaixo estão alguns exemplos.

Para instalar a versão mais recente do “SomeProject”:

Unix/macOS
python3 -m pip install "SomeProject"

Windows
Para instalar uma versão específica:

Unix/macOS
python3 -m pip install "SomeProject==1.4"

Windows
Para instalar uma versão igual ou superior a uma e inferior a outra:


Unix/macOS
python3 -m pip install "SomeProject>=1,<2"

Windows
Para instalar uma versão compatível com uma determinada versão: [ 4 ]


Unix/macOS
python3 -m pip install "SomeProject~=1.4.2"

Windows
Neste caso, isso significa instalar qualquer versão “==1.4.*” que também seja “>=1.4.2”.

Distribuições de origem vs. rodas 
O pip pode instalar a partir de distribuições de código-fonte (sdist) ou de pacotes wheel , mas se ambos estiverem presentes no PyPI, o pip dará preferência a um pacote wheel compatível . Você pode sobrescrever o comportamento padrão do pip, por exemplo, usando a opção `--no-binary` .

Os wheels são um formato de distribuição pré-compiladoque proporciona uma instalação mais rápida em comparação com as distribuições de código-fonte (sdist) , especialmente quando um projeto contém extensões compiladas.

Se o pip não encontrar um pacote wheel para instalar, ele criará um pacote wheel localmente e o armazenará em cache para instalações futuras, em vez de recompilar a distribuição de origem posteriormente.

Instalando “Extras” 
Os extras são "variantes" opcionais de um pacote, que podem incluir dependências adicionais e, assim, habilitar funcionalidades extras do pacote. Se você deseja instalar um extra para um pacote que você sabe que publica um, você pode incluí-lo no comando de instalação do pip:


Unix/macOS
python3 -m pip install 'SomePackage[PDF]'
python3 -m pip install 'SomePackage[PDF]==3.0'
python3 -m pip install -e '.[PDF]'  # editable project in current directory

Windows
